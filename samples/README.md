# VoiceDesk samples

These examples are generated locally from the existing Django API with
`samples/generate_samples.py`. They use a disposable Django test database and a
temporary media directory; they do not modify `backend/db.sqlite3`.

## Files

- `synthetic_complaint.wav` is a short, silent PCM WAV generated by Python's
  standard-library `wave` module. It is a synthetic upload placeholder, not a
  real recording and contains no speech.
- `complaint_submission_input.json` documents the actual multipart form fields
  and file metadata accepted by `POST /api/complaints/`. The generator uploads
  the WAV in the `audio` field.
- `complaint_submission_response.json` is the actual response from a local
  Django test-client complaint submission. Its ticket UUID is redacted.
- `classification_response.json` contains the classification fields extracted
  from that same generated submission response. Classification runs through
  the application's existing deterministic rules on the synthetic English
  translation.
- `ticket_lookup_response.json` is the actual response from
  `GET /api/complaints/<ticket_uuid>/` after the reply workflow. The ticket UUID
  is redacted.
- `agent_reply_response.json` is the actual response from the authenticated
  agent-reply endpoint. The synthetic Hindi translation is mocked, and the
  TTS adapter is mocked to fail. Therefore the saved text and failure status
  are representative API output; no audio was generated.

## Generation and reproduction

The generator mocks denoising, speech-to-text, translation, and TTS. It never
makes live AudicLabs or Google Cloud requests. The transcript and translations
are synthetic test values, not provider results. The category, priority, and
summary are produced by the project's real local classification function.

From the repository root, with dependencies installed in `.venv`, run:

```powershell
Set-Location backend
..\.venv\Scripts\python.exe ..\samples\generate_samples.py
```

To run the project's existing complaint tests separately:

```powershell
Set-Location backend
..\.venv\Scripts\python.exe manage.py test complaints
```

The sample request manifest uses the endpoint's actual multipart fields:
`customer_phone` (10 digits), `language` (language code), and `audio` (an
uploaded file whose content type starts with `audio/`). The synthetic phone
number is reserved for fictional use. No photo is included; it is optional.

Generated ticket UUIDs and timestamps vary between runs. UUIDs in the sample
output files are replaced with `[REDACTED-TICKET-UUID]`; the agent reply
response does not contain a ticket UUID. These are local test-client outputs,
not results from the live providers and not evidence of live transcription,
translation, or TTS quality.
